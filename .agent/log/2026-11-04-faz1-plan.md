## Decisions (and why)
1. **Bidirectional dual-write for `AutomationStep` + `AutomationEdge` (`ROADMAP.md` §5.1):**
   - `AutomationWriteSerializer` accepts either legacy `actions` or `steps` + `edges` and keeps both tables synchronized (`sync_steps_from_actions` / `sync_actions_from_steps`).
   - `AutomationOrchestrator` uses `execute_actions()` for plain linear action chains and switches to `execute_graph()` when non-action steps, branch edges, resumed waits, or step-only flows are present.
2. **SSTI-safe custom expression engine (`engine/expressions.py`):**
   - Built with zero `eval`/`exec`/Jinja2, supporting dotted paths, array indices, pipe filters (`default`, `upper`, `lower`, `strip`, `title`, `length`, `currency`, `date`, `json`), and `{%if ...%}...{%endif%}`, while preserving native Python types for single-placeholder expressions (`"{{steps.1.output.count}}"` -> `int`).
3. **Runtime adapter outside `engine/` (`apps/automations/runtime.py`):**
   - Isolates all Django ORM, signal, DRF serializer, and Celery task calls outside `apps/automations/engine/`, bringing engine purity violations from 9 down to **0**.
4. **Hardening from adversarial review:**
   - Added `_validate_tenant_boundary` in `AutomationWriteSerializer` so a tenant cannot attach another tenant's `Channel`, `Template`, or `source_automation_id`.
   - Clamped `_chain_depth` to `>= 0` in `runtime.py` so negative `_chain_depth` in untrusted payloads cannot bypass `MAX_CHAIN_DEPTH = 5`.
   - Enforced `1 <= timeout <= 60` on `http_request` at both serializer and runtime layers.
